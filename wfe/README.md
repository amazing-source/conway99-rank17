# wfe — per-class witness-filtered frame engine (structures, 28/09 night)

Status at 28/09 ~20:45: paused on the user's stop. No production run was made. The engine is built and validated, and
the tree sizes are measured.

## What it does
For one class (V, y-pair), with K = V ∩ y^⊥, the engine looks for the 21-cell frame (w⁺, w⁻) using every dual vector
κ ∈ K* with 7|κ|² = n ≤ 8 (the "witnesses"). The values a_u = (κ, w_u) must satisfy:
- **Parseval:** Σ_u a_u² = 4n. This comes from the tight frame Σ w wᵀ = 28 P_W.
- **Cross identities:** Σ_u a_u(κ) a_u(κ′) = 28(κ, κ′) for every pair of witnesses.
- **Cauchy–Schwarz:** |a_u| ≤ √(10n/7).
- **Parity:** the parity of a_u is fixed by the skeleton cut, p_c = (κ, g_c) mod 2.
- **C1-validated k-rules** (k = cut size):
  - n=5: k=2, odd labels ±1, even labels 0;
  - n=6: k ∈ {2,3}; for k=2 exactly one ±2;
  - n=8: k ∈ {1,2,3}; odd ±1, even {0,±2}.
  - For n=7 only Parseval, C-S and min N* are used.

Files:
- `wfe.py`: witnesses, the per-vector filter, C1's `Case` and domains, and a Python vector level (`vector_level`, reference implementation).
- `sbdfs_w.c`: sbdfs_g plus linear budget constraints.
- `wfe_c.c`: the whole pipeline in C.
  - **Skeleton search:** C1's rules, the witness o-rules, and two new lossless symmetry reductions.
    - *S7 base line:* g₂ is the smallest of the 21 cell classes.
    - *Lexmin stabilizer pruning:* at every depth, t_{j+1} must be minimal in its orbit under the group generated by the root transvections that fix t₁..t_j. The argument is valid for any subgroup of the pointwise stabilizer.
  - **Leaf:**
    - a table pre-check;
    - an exact pair-level check: M1, refined L1, exact-k values, all witness-pair budgets with fixpoint propagation, and pair arc consistency;
    - the sbdfs search in K coordinates with dynamic budget bounds.
- `wfe4.py`: the driver (export, then est/run/check).
- `wfe2.py`, `wfe3.py`, `skel_w*.c`: earlier stages, kept for the record.

## Validation
On 129 sampled E8:5 skeletons, `wfe_c check` agrees with the Python `vector_level` stage by stage (budget ↔ budget,
empty ↔ empty, search ↔ search). All 129 are excluded.
- The pair-level propagation and arc consistency move 12 of the 15 search cases into the exact check.
- The verdicts are unchanged by every optimisation.
- Script: `cvalid.py`.

## Measured tree sizes
Knuth estimates, 20k walks, STABMAX=5.

| class | witnesses | leaves (skeletons after all reductions) |
|---|---|---|
| E8:5 | n5×4, n6×6, n7×1, n8×8 | ~3e5–8e5 (was ~1e11 before the stabilizer pruning) |
| A11E6p:9 | n6×5 | 1.6e9 |
| A11E6p:8 | n6×2, n8×6 | 1.2e10 |
| A11E6p:10 | n8×6 | 4.7e10 |
| A11E6p:12 | n8×3 | 4.5e10 |
| A15p:42 | n6×3, n8×2 | 1.1e10 |

Cost is ~1 ms per leaf.
- **n=5 classes (E8:5 type):** feasible, about 15 min per class per thread. General R5 (C1, engine validated, ~4 h run
  paused) would take all 412 at once.
- **min-6 and min-8 classes:** infeasible as they stand (1e9–5e10 leaves).

**Hypothetical gain (measurement only, not a proof step).** On A11E6p:8:
- if R8 k=2 and k=3 were proven, every n=8 witness would be restricted to k=1 and the leaves drop 1.2e10 → **2.1e6**
  (feasible);
- if in addition J2 were closed (n=6 ⇒ k=3), there are **0 skeletons**.

So general R8 k=2, R8 k=3 and J2, the targets of C1's cut engine, turn the remaining 342 classes into per-class runs of
minutes. Script: `est_hyp.py`.
